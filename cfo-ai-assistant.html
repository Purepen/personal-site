AI Engineering

CFO AI Assistant

A team of specialized AI agents that answer a Nigerian bank CFO's financial questions in plain English, pulling from real financial data, internal policy documents, and live market intelligence, in seconds instead of hours.

Claude Sonnet 4 Multi-agent Text-to-SQL RAG FastAPI PostgreSQL

A CFO's day is full of questions that live in different places. The board wants the capital adequacy ratio right now, not after thirty minutes of spreadsheet archaeology. An auditor wants NPL trends pulled from three different systems. A manager wants to know whether they can approve a ₦35 million expense without digging through a policy PDF to find the threshold. None of that is hard to answer, it's just scattered.

The CFO AI Assistant puts one conversational interface in front of all of it. Ask a question in plain English and a router sends it to whichever specialist agent actually knows the answer: a text-to-SQL agent for financial metrics, a RAG agent for policy and compliance documents, and a web agent for market intelligence. I built two versions of this, and the gap between them is basically the story of learning to build agent systems properly.

v1: proving the idea

The first version ran on Claude Sonnet 4 and LangChain with three agents: SQL for structured financial metrics, RAG over ChromaDB for policy documents, and a web search agent for anything current. It could already do the core trick, turn "show banks with ROE above 20%" into a real query against a SQLite database of 15 Nigerian banks, or answer "what's the approval threshold for a ₦50M loan" by retrieving the right paragraph from a policy document instead of making the CFO go find it. That version is open on GitHub if you want to see where this started.

v2: built like it's going into production

Version 2 is a full rebuild around a proper microservices shape: a Streamlit frontend, a FastAPI backend, an orchestration layer that routes queries, and five agents instead of three, adding a Compliance agent that checks live ratios against CBN thresholds and classifies violations by severity, and a Financial Analyst agent that does trend detection and 3-to-6-month forecasting with confidence intervals. The data layer moved from SQLite to PostgreSQL, normalized to third normal form across seven core tables (balance sheet, profit and loss, regulatory ratios, loan portfolio, competitor data, users, and an immutable activity log), and the whole thing runs on Claude Sonnet 4, whose 200,000-token context window is what makes it practical to reason over an entire policy document in one pass instead of chunking around the important part.

Security got the same production treatment: role-based access across CFO, manager, and analyst tiers, JWT sessions, parameterized queries throughout, and an append-only audit log of every action. It's the difference between "a demo that works" and "something I'd actually hand to a bank."
