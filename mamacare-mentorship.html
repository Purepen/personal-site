MamaCare: Teaching a Cohort to Ship an ML + LLM App

An 8-week mentorship project for 3MTT, WeSonline, and Data Science Nigeria students: a maternal health risk model wrapped in an LLM advisor, taken all the way from a raw CSV to a live, public app.

Mentorship scikit-learn XGBoost Groq / Llama 3.3 Gradio Hugging Face Spaces

For Cohort 3 of a joint 3MTT, WeSonline, and Data Science Nigeria mentorship track, I spent 8 weeks guiding a group of mentees through one full project, start to finish: MamaCare, a maternal health risk advisor. The brief was simple to say and genuinely useful to build: take a patient's basic vitals, predict a risk level with a trained model, then have an LLM turn that prediction into warm, practical advice a pregnant woman could actually act on.

What made this a good teaching project is that it forces you through every stage a real ML product goes through, not just the fun modeling part. We covered model comparison and tuning, prompt engineering for a sensitive domain, the unglamorous work of turning a notebook into a script, and finally deployment, including the platform gotchas nobody warns you about until you hit them mid-class.

Part 1: choosing a model for the right reason

We trained four classifiers, a Decision Tree, Gradient Boosting, XGBoost, and an SVC, on 1,014 patient records after removing 562 duplicate rows that would otherwise have leaked between train and test. The lesson that stuck with the cohort: SVC posted the highest raw accuracy, but the lowest macro F1, because it was coasting on the majority "low risk" class while quietly failing the "high risk" patients, the ones a screening tool actually exists to catch. We ranked by macro F1 instead of accuracy for exactly that reason, tuned the winner with GridSearchCV under 5-fold cross-validation, and shipped it as a single scikit-learn pipeline (scaler plus model) so deployment would be one joblib.load() away from a working prediction.

Part 2: giving the prediction a voice

A risk label on its own doesn't help a worried mother. So the second half of the project added an LLM, Llama 3.3 70B via Groq's free tier, since neither OpenAI nor Anthropic offer a free API and this needed to cost nothing for every student. The real work here was the system prompt: it packs in normal reference ranges for each vital, a rule to always personalize the advice to the patient's actual numbers, a hard rule to never diagnose or prescribe, and a requirement that any high-risk result opens with "see a doctor promptly." Temperature stayed at 0.4 throughout, because health advice should be consistent, not creative.

Part 3 and 4: from notebook to a link anyone can open

The last stretch is the part most tutorials skip: turning a notebook into a product. We moved model loading and the API client to module level so nothing reloads on every click, swapped input() for a Gradio interface, replaced the notebook's friendly getpass fallback with a loud failure if the API key is missing (a deployed server has nobody at the keyboard to prompt), and wrapped the core function in Gradio's error handling so a stranger leaving a field blank gets a clear message instead of a stack trace. Then we deployed to Hugging Face Spaces, and hit a genuinely useful real-world lesson along the way: Hugging Face now requires an account to be over 30 days old before it can host even a free Gradio Space, a platform rule with no workaround, and exactly the kind of thing you only learn by trying to ship for real.
